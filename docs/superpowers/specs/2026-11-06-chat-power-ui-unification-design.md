# Chat-Power 会话区 UI 统一改造设计

## 目标

把 chat-power 各功能从“各功能一套交互与样式”收敛为同一套轻量工作台、文档式阅读面板、统一编辑器和统一发送链路。改造只改浏览器半边的会话区体验，不改宿主右侧栏、不改变已确认的功能范围与发送边界。

## 成功标准

1. 所有新增或改动表面使用同一组颜色、间距、尺寸、图标和状态 token；文件阅读区不再以局部深色媒体查询另做一套暗色样式。
2. 工作台第一层只承载工具入口，第二层只承载资源标签；窄窗口、1 个与 20 个标签时都不换行、不遮正文。
3. 答案、本机文件、单段选区、多段收集和会话尾部文件使用可辨识的编辑与发送模型：来源明确、动作顺序一致、发送成功前不丢失草稿。
4. 文件树、选区弹条、多签收集、批注和 Mermaid 的失败与加载状态可感知，且都能在键盘与触屏条件下使用。
5. 浅/深主题、窄窗口、长路径、多标签、多段收集与发送失败恢复均通过验证；现有 117 项测试不回退。

## 范围与非目标

- 改：`conversation-tools`、文件树、文件阅读与批注、选区与多选、答案卡片、本机文件、Mermaid、内置浏览器/终端外壳（chat-power 控制部分）、链接偏好、短会话 ID、Markdown 宽表。
- 不改宿主右侧栏、不新增独立右侧栏、不改变 agent 接入与 ACP 进程段职责、不重排宿主会话输入区。
- 浏览器与终端正文仍由宿主工厂渲染；宿主未暴露的接口不越权扩展。
- 本轮不引入账号、同步、协作、文件预览扩展、分屏、拖出窗口等能力。

## 已确认的设计决策

1. 工作台为固定 36px 第一层与单行第二层：会话 / 工作区文件 / 浏览器 / 终端，右侧放“打开本机文件”图标与“更多”；链接偏好、刷新、外部打开等次操作进入“更多”。
2. 统一数值基线：间距 4/8/12/16/24px；正文 14px、辅助信息 12px；控件半径 6px、面板 10–12px；图标 16px、桌面点击区 32px；内容卡片 10–12px；悬浮层阴影、内容卡片轻边框。
3. 统一动作语义：复制、取消、发送到当前会话、新建会话并发送；低频或破坏性动作放“更多”。新建会话不叫“分支会话”，因为它不会携带完整会话历史。
4. 统一发送链路：空白禁用；提交中锁定并防重复；请求成功后才关闭/退出编辑并清理；失败保留内容并给出可重试反馈；取消与失败不销毁草稿。
5. 文件与选区编辑都明确为“发送副本”：正文旁保留一次性说明，不暗示修改会落盘；磁盘工作区文件仍保留宿主预览。
6. 选区操作文案为“加入草稿 / 立即发送 / 添加批注 / 收集 / 编辑 / 收集编辑”，发送目标在 tooltip 中说明。
7. Mermaid 默认图表面板宽度自适应；复杂图进入放大视图，图表头统一使用文件卡同款的轻量工具栏。复制明确为“复制源码”。
8. 文件组标题为“本轮文件 · n”；默认前 4 项，其余为“显示其余 n 个 / 收起”。

## 架构与模块边界

- `ui-theme.ts`：集中导出主题 token、图标按钮、面板、菜单、状态反馈的基础 CSS；不承载业务功能。
- `send-actions.ts`：集中发送请求、pending、失败反馈、成功回调与文本校验，供答案、文件、选区与批注复用。
- `compose-card.tsx`：统一的标题、说明、正文、动作栏编辑器外壳；通过 variant 适配答案、本机文件、选区、工作区文件与普通文件，但不改变各功能的数据流。
- `conversation-tools.tsx`：只保留工作台装配、打开资源、链接策略与宿主副作用；标签呈现与状态从布局细节中拆出。
- `tools-state.ts`：继续管理标签生命周期；补“是否含未发送草稿”标记，供关闭前恢复提示使用。
- `file-tree-augment.tsx`：只装饰宿主文件树；不改变文件排序、宿主节点结构与宿主右侧栏。
- `markdown-turn.tsx`：保留读取、滚动锚定、发送、评论锚点；UI 只使用统一组件，不改变文档解析。
- `mermaid.ts`：DOM 增强只负责 Mermaid 预览头、放大视图与失败状态；不触碰原生代码块内容。
- `selection-actions.ts`：保留纯 DOM 弹条与收藏 store；样式迁移到统一 token，不改成另一套 React 组件。

## 主要状态与数据流

1. 工具入口切换不创建重复资源；文件、浏览器、终端复用已有标签。普通外链默认复用当前浏览器标签，避免销毁正在阅读的页面。
2. 编辑中的文件、选区、答案持有本地草稿；切换标签保留本地状态。发送请求以“发送成功”为唯一清空条件；失败时保留正文、批注与收集内容。
3. 批注以文档原文锚点渲染在对应段落后，底部汇总显示“待发送 n 条”；发送失败不清空汇总。
4. 多选收集绑定当前会话，切换会话自动隐藏；20 段时收集面板内部滚动，不覆盖正文。
5. Mermaid 预览使用源码主题与缓存；失败保留源码并显示原因，加载中显示轻量状态，不静默回退。

## 错误处理

- Clipboard、文件读取、发送、打开外部应用、Mermaid 加载/渲染都必须在相关区域给出状态或原因；不能只写 console。
- 请求 pending 期间禁用重复提交与关闭/收起，避免竞态。
- 空文本禁用发送；复制失败给出可恢复提示。
- 文件树写入引用失败时保留原 checkbox 状态，并在工具区显示统一 inline notice。
- 宿主能力缺失时隐藏对应能力，但保留可替代动作（如复制路径）。

## 可访问性

- 图标按钮均有可访问名称，tab/toolbar/菜单分别使用对应语义。
- 焦点态使用宿主 focus 变量，不靠 hover 表达唯一可用性。
- 键盘方向键、Tab、Escape、Delete 按既有功能边界保留；新增“更多”菜单支持宿主 Menu 的键盘操作。
- 状态不单靠颜色：成功/失败使用图标与文字，终端状态使用图标与 tooltip/文字。

## 测试策略

- 单元测试：工具状态与草稿、统一发送请求、链接策略、文件组折叠、批注锚点与汇总发送、选区位置与资格、会话作用域、ID 展示。
- DOM 注入测试：文件树装饰、Mermaid 状态与预览头、选区弹条样式注入与动作委托。
- 构建与装载：`npm run typecheck`、`npm test`、`npm run build`、`bundle.spec` 与产物格式测试。
- 浏览器人工验收：浅/深主题、窄/宽窗口、长路径、多标签、多段选区、发送失败、文件树键盘/触屏、Mermaid 宽图与放大、终端与浏览器外壳。
